# 🐳 Jakarta EE Docker Labs (Базовая платформа для лабораторных)

Привет 👋

Этот репозиторий --- **базовая инфраструктурная платформа** для
выполнения лабораторных работ.

Он уже содержит:

- 🐳 Docker
- 🌐 GlassFish 8
- 🗄 PostgreSQL (если используется)
- ⚙ Настроенную среду
- 📦 Базовый пример приложения

Вам НЕ нужно настраивать Java, сервер или БД вручную.

---

# 📌 Как работать с этим репозиторием

## 1️⃣ Клонируем проект

```bash
git clone https://github.com/AngryDivan/jakarta-ee-docker-labs.git
cd jakarta-ee-docker-labs
```

## 2️⃣ Запускаем

```bash
docker build -t lab-demo .
docker run --rm -p 8080:8080 -v lab_pg:/var/lib/postgresql/data lab-demo
```

# После запуска:

Демо-приложение:\
http://localhost:8080\
localhost:8080/lab-demo - демонстрация работы контейнера\
localhost:8080/lab-demo/api/tasks - база данных\
mvn -pl fx-client javafx:run - (в отдельном Bash терминале) запуск клиента демострационного приложения

Если у вас это запустилось без ошибок - значит все работает.

# 🖥 Демонстрационное приложение

В проект уже встроено полноценное демонстрационное Jakarta EE приложение `lab-demo`.

Оно показывает работу:

- Jakarta EE
- GlassFish
- REST API
- JPA/JDBC
- PostgreSQL
- JavaFX
- Docker

в рамках одного контейнеризированного проекта.

---

# 🏗 Архитектура приложения

Проект состоит из двух основных частей:

## 🌐 Server (`server`)

WAR-приложение, автоматически разворачиваемое на GlassFish.

Используемые технологии:

- Jakarta Servlet API
- Jakarta REST (JAX-RS)
- JSF
- JPA
- JDBC
- PostgreSQL
- GlassFish 8

Серверная часть:

- принимает HTTP-запросы;
- обрабатывает REST API;
- взаимодействует с PostgreSQL;
- хранит задачи;
- возвращает JSON-ответы клиенту.

---

## 🖥 JavaFX Client (`fx-client`)

Desktop-клиент на JavaFX.

Используемые технологии:

- JavaFX
- HttpClient
- TableView
- ObservableList

Клиент подключается к серверу через REST API и позволяет:

- просматривать задачи;
- добавлять задачи;
- менять статус выполнения;
- удалять задачи.

---

# ⚙ Логика работы приложения

## 📌 Получение списка задач

JavaFX-клиент отправляет GET-запрос:

```text
GET /lab-demo/api/tasks
```

Сервер:

1. получает данные из PostgreSQL;
2. преобразует их в JSON;
3. отправляет клиенту.

После этого JavaFX отображает задачи в `TableView`.

---

## 📌 Создание задачи

При добавлении новой задачи:

1. пользователь вводит название;
2. JavaFX отправляет POST-запрос;
3. сервер создает новую запись через JPA;
4. PostgreSQL сохраняет данные;
5. клиент обновляет таблицу.

---

## 📌 Изменение статуса задачи

При нажатии кнопки Toggle:

1. отправляется запрос на сервер;
2. меняется поле completed;
3. база данных обновляется;
4. интерфейс автоматически перерисовывается.

---

## 📌 Удаление задачи

При удалении задачи:

1. клиент отправляет DELETE-запрос;
2. сервер удаляет запись через JPA;
3. PostgreSQL фиксирует изменения;
4. JavaFX обновляет таблицу.

---

# 🔌 REST API

Базовый адрес API:

```text
http://localhost:8080/lab-demo/api/tasks
```

Основные запросы:

| Метод  | Назначение            |
| ------ | --------------------- |
| GET    | Получить список задач |
| POST   | Создать задачу        |
| PUT    | Изменить задачу       |
| DELETE | Удалить задачу        |

# ⚡ Автоматизация запуска

При запуске контейнера автоматически:

1. собирается WAR-файл;
2. запускается GlassFish;
3. создается JDBC Pool;
4. создается JDBC Resource;
5. деплоится приложение `lab-demo`;
6. запускается сервер.

Все это выполняется автоматически через `entrypoint.sh`.

# 🎯 Как выполнять лабораторные?

## 🥇 Рекомендуемый вариант (самый правильный)

Оставить этот репозиторий как **базовую платформу**, а лабораторные
делать как отдельные модули внутри него.

То есть:

    jakarta-ee-docker-labs/
    │
    ├── server/          ← основной backend
    ├── fx-client/       ← JavaFX клиент
    ├── labs/
    │   ├── lab1/
    │   ├── lab2/
    │   ├── lab3/
    │   └── ...

Каждая лабораторная:

- это отдельный Maven module
- собирается как отдельный WAR или JAR
- деплоится в уже настроенный GlassFish

---

# 🧱 Как создавать новую лабораторную

## 🔹 Шаг 1. Создать Maven module

В папке:

    labs/

Создать новый модуль, например:

    lab1/

Он будет отдельным проектом (своим pom.xml).

---

## 🔹 Шаг 2. Тип лабораторной

### Если это JavaFX

Работаем в:

    fx-client/

или создаём отдельный fx-модуль в labs.

---

### Если это JSF / Jakarta EE

Создаём WAR внутри:

    labs/labX/

---

## 🔹 Шаг 3. Сборка

После добавления лабораторной:

```bash
docker build -t lab-demo .
```
